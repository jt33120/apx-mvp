- (constraint) INHERITED, binding: the payload schema (RBAC scope, provenance, matter, dates) is the only irreversible decision in the increment. Adding a field later means re-indexing everything at every installed site, blind.
- (constraint) INHERITED, binding: deployment-agnostic core with tenant isolation as a day-one invariant. SaaS vs on-premise is a packaging decision per client, never an architecture.
- (constraint) INHERITED, binding: customisation is DATA, never code. Taxonomy, RBAC scopes, LLM provider, sources are configuration rows. No per-client fork, ever.
- (constraint) INHERITED, binding: fitness function — can this run, UNMODIFIED, on a single machine inside a law firm with no internet connection? Anything that fails it goes behind an adapter. FR-55 makes this a CI job.
- (constraint) INHERITED, binding: Supabase / Vercel / Railway acceptable for development and a hosted tier only. Plain PostgreSQL yes; Supabase Auth and Supabase RLS forbidden — they would make on-premise installation impossible.
- (constraint) INHERITED, binding: RBAC scope is a PRE-FILTER on the retrieval query, never a post-filter. Cross-matter leakage is the #1 realistic leak vector and a post-filter leak is silent.
- (constraint) INHERITED, binding: never hard-delete. Triage is reversible labelling over one ranked order; the retained and discarded sets are VIEWS, not memberships.
- (constraint) INHERITED, binding: two engines with different truth status — semantic (top-k, suggestive) and deterministic (exhaustive, complete match set). Truth status is a property of every result set, carried in data, present in exports and in the audit record.
- (constraint) INHERITED, binding: EU-only, zero-retention, only code travels inbound. Client data never leaves the firm. The content-free projection is one reusable primitive with the content-freedom property enforced structurally, not by an allow-list.
- (constraint) INHERITED, binding: judgement cascade — cheap deterministic filters and dedup first, LLM judgement only on the uncertain band. Per-piece LLM judgement at 100k documents is the largest inference cost AND the largest egress event in the system; a fully local model may be necessary rather than premium.
- (constraint) INHERITED, binding: design target 100 000 pièces per matter. Team is one non-hands-on lead plus AI agents, so tests substitute for the engineers who are not there — every invariant must be verifiable in CI, not merely stated.
- (direction) Working mode: show-and-choose. Load-bearing calls (paradigm, stack, major boundaries, the payload schema) are presented with real alternatives and a recommendation; the user decides. Everything else is decided and tagged [ASSUMPTION]. Deliverables: the spine, plus a work-breakdown view for the epics step.
- (decision) AD — PIECE IDENTITY IS SCOPED TO ONE MATTER. Binds: ingestion, identity/dedup, retrieval filtering, audit. Prevents: two units disagreeing on whether a pièce is one object seen from several matters or several independent objects — which would produce incompatible identity keys, incompatible dedup semantics and an ambiguous Chinese wall. Rule: a pièce's identity is (content hash, matter). The same file ingested into two matters yields two pièces with separate identities, rankings, audit records and lifecycles. No entity in the system is visible from more than one matter. Cross-matter deduplication and 'seen before' intelligence are explicitly forfeited — they are the capability a Chinese wall exists to forbid. Consequence: the scope predicate is an EQUALITY, the filter shape hardest to get wrong.
- (decision) AD — RBAC SCOPE IS RESOLVED AT QUERY TIME FROM A SINGLE AUTHORITATIVE SOURCE, NEVER DENORMALISED ONTO INDEXED ROWS. Binds: every retrieval path, the payload schema, admin operations on scopes. Prevents: a stale wall — the E-1 defect where scope is stamped at index time, scopes are editable configuration and nothing re-stamps, so an ordinary admin act silently enforces obsolete permissions. Rule: authorisation state lives in exactly one place and is joined into every retrieval query as a pre-filter; a scope change takes effect on the next query with no re-indexing, no migration and no window of indeterminate state. Cost accepted: a join per query. Obligation created: exactly one code path may construct a retrieval query, and its uniqueness is a structural property asserted in CI (FR-56) — the join must be impossible to bypass rather than merely conventional.
- (constraint) Follows from the two decisions above: no re-stamping operation exists in the system, so the long-running rewrite that fails halfway on an unreachable machine is designed out rather than made recoverable. Revocation reaches live sessions because it is read per query.
- (version) Verified 2026-07-21 against primary sources (docs/context/05-stack-research-2026-07.md): PostgreSQL 18.4 (released 2026-05-14; PG19 is at Beta 2 and must not ship into a firm), pgvector >= 0.8.5, Procrastinate 3.9.x, BGE-M3 (568M, 1024-dim, MIT), Tesseract 5.5.2, Mistral Small 3.2 24B (Apache-2.0), vLLM pinned by digest.
- (decision) AD — ONE STATEFUL SERVICE. PostgreSQL 18.4 holds relational data, vectors (pgvector, HNSW, 1024-dim halfvec) and the job queue (Procrastinate). Binds: storage, retrieval, ingestion, deployment, backup. Prevents: units independently introducing a second stateful service (Redis for the queue, Qdrant for vectors) and producing a deployment a non-specialist cannot operate, back up or restore. Rule: no component may introduce a stateful service beyond PostgreSQL; anything that appears to require one is an adapter boundary, not a new deployment unit. Consequences: crash-resume mid-100k-ingestion becomes a transaction property rather than a configuration; the dev tier and the air-gapped install run literally the same component. Known risk: HNSW memory above ~8M chunks on a small machine; the escape hatch (pgvectorscale StreamingDiskANN) is not available on the managed dev tier, so it would be an on-prem-only path. Measure real chunk yield on a 100k-document corpus before this is load-bearing, and keep the vector column type behind a migration.
- (decision) AD — 1024 DIMENSIONS IS THE INTERFACE, THE EMBEDDER IS SWAPPABLE. Binds: chunk schema, retrieval, any re-embed. Prevents: a model choice becoming a schema migration. Rule: the vector column is 1024-dim halfvec; every chunk row carries model_id and model_version; changing embedder is a background migration, never a rebuild. BGE-M3 is the default (MIT, 1.4GB, dense AND sparse from one pass — sparse matters for French legal names, references and article numbers, where dense-only retrieval classically fails); multilingual-e5-large-instruct is a drop-in fallback; Qwen3-Embedding-0.6B is the same-family upgrade. Honest risk carried forward: BGE-M3 is a 2024-generation model measurably behind the 2026 frontier (51.8 vs 56.4 BEIR), and if retrieval quality turns out to be the binding constraint on triage recall — which for legal discovery it may well be — the upgrade path costs hardware.
- (decision) AD — TWO INFERENCE PROFILES BEHIND ONE OPENAI-COMPATIBLE INTERFACE, SELECTED BY CONFIGURATION. User decision, 2026-07-21: APX ships both a GPU profile (vLLM, pinned digest, Mistral Small 3.2 24B at INT8/Q4 on 24GB VRAM — 100k pièces overnight) and a CPU/low-end profile (Ollama — the same job in two to three weeks), priced differently. Binds: every inference call site. Prevents: application code branching on which engine is behind it, and a per-profile code fork. Rule: application code never knows which engine serves it; the profile is configuration-as-data, and the expected wall-clock for the chosen profile is stated honestly to the firm before the job starts. Commercial note: the CCBE's March 2026 guide publicly prices law-firm hardware at 2000-20000 EUR, so the GPU ask cites the profession's own guidance rather than sounding exotic.
- (constraint) The cascade is load-bearing, not an optimisation: cutting the LLM's workload 10x is far cheaper than 10x the GPU, and it is the difference between the 2000 EUR machine and the 20000 EUR one. Order: deterministic filters (content-hash dedup, sender/date rules, attachment type) -> vector + BM25 retrieval -> LLM judgement on survivors only.
- (decision) AD — THE FRONTEND IS A STATIC SPA (Vite 8.1.5 + React Router 8.2.0); Next.js is dropped. User decision, 2026-07-21. Binds: every data access path, the deployed artefact, the authorisation surface. Prevents: a second place where matter scope can be wrong — a server-rendering layer that fetches data is a second query path, in a second language, and it contradicts the standing rule that exactly one code path may construct a retrieval query. Rule: the client is static assets; all data access is HTTP to the one API; no rendering layer holds credentials or performs authorisation. Consequences: no Node runtime and no Next patch debt inside an artefact that cannot be patched remotely; Next 16's caching architecture — a liability under a per-matter wall — is removed with it. Note: Next.js does work offline (telemetry is build-time, fonts self-hosted at build), so this is not a functionality argument. v1's React components port; the Next scaffolding is what is discarded, not the interface work.
- (decision) AD — AUTHENTICATION IS OWNED, NOT DELEGATED. Opaque server-side sessions in PostgreSQL + Argon2id via pwdlib[argon2] 0.3.0; PyJWT 2.13.0 for internal service tokens ONLY, never for user sessions; pyotp 2.10.0 for 2FA; py_webauthn 3.0.0 as an additive credential gated on a per-site FQDN and certificate. Binds: every authenticated request. Prevents: a unit reaching for a managed identity provider (forbidden — it breaks the air-gapped install) or for a library that is dead or CVE-ridden. REJECTED WITH REASONS, recorded so they are not revisited: FastAPI-Users (maintenance mode since v15.0.1), python-jose (CVE-2024-33663, authentication bypass; 3 releases in 5 years), passlib (unmaintained since 2020), Authlib (12 advisories including CVE-2026-27962, CVSS 9.1 signature-verification bypass patched only in 1.6.9, 2026-03-15) unless OIDC is contractually forced. This is what the official FastAPI documentation now teaches.
- (decision) AD — OFFLINE PACKAGING AND UPGRADE. Docker Compose bundle (Engine 29.6.2, Compose v5.3.1) delivered as a docker save tarball; cosign 3.1.2 KEY-PAIR signing verified --offline by the installer (keyless verification needs Fulcio/Rekor and is unusable air-gapped); upgrade.sh takes a verified pg_dump before every Alembic 1.18.5 migration and FAILS CLOSED; rollback is dump restore plus recorded image digests, never alembic downgrade. Binds: release, install, upgrade, rollback. Prevents: an unattended migration on an unreachable machine leaving a half-migrated database with no way back. Ruled out: a single binary (the stack shape — PostgreSQL plus native extensions — forbids it) and Tauri (additive only, though it would dissolve the WebAuthn secure-context problem).
- (question) OPEN RISK 1 — pgvector as the sole store is falsified by a measured chunk yield above ~8M on a real 100k-document corpus, or HNSW p95 above 2s. MUST be measured before any retrieval code is written.
- (question) OPEN RISK 2 — the no-identity-provider assumption is falsified by the first customer security questionnaire demanding SAML/OIDC, which drags CVE-heavy Authlib onto the critical path. Watch for it in the first procurement conversation.
- (question) OPEN RISK 3, THE SHARPEST — nobody summed the machine. Sections 3, 4 and 5 each sized the same 2000 EUR box independently, as if OCR, embedding and LLM inference each had it to themselves; during an ingestion all three run concurrently. Falsified by a TIMED 5000-DOCUMENT RUN with OCR, embedding and LLM judgement concurrent. Until that number exists, every wall-clock promise in the PRD is speculation. This is the first thing to measure, before any feature code.
- (event) Upstream corrected rather than left to diverge: PRD FR-49 amended 2026-07-21 to match AD-13. The behavioural guarantee is unchanged and strictly stronger — immediate rather than eventual, with no half-migrated window — but the re-stamp MECHANISM is gone. - (decision) AD — ENCRYPTION LAYER SPLIT, resolving spine open question 1. User decision 2026-07-21. Binds: every storage adapter, the startup gate, the security questionnaire answer. Prevents: units either building an unsatisfiable application-layer encryption of indexable columns, or silently leaving searchable surfaces unencrypted with nobody having decided it. Rule: everything except two surfaces is encrypted by the application's storage adapters; the VECTOR COLUMN and the DETERMINISTIC TEXT INDEX are named exceptions protected by volume- or cluster-level encryption on a machine the firm owns — not a third party's volume service, so the requirement's intent (a stolen disk or a restored backup yields nothing) holds while both indexes stay buildable. Startup fails closed on BOTH layers: missing application key or unencrypted data volume. FR-47 amended in the PRD the same day with a dated note, so the spine and its source do not diverge.
