- (decision) Visual identity is RATIFIED from apx/web/src/tokens.css (AD-29), not re-elicited. It is this rebuild's own design system — navy ink #0b1f3a, a single gold accent #9a7a34, warm paper #f7f4ee, semantic tier distinct from the accent (kept/review/discard/danger), serif for wordmark+headings, sans for the interface, mono for identifiers. DESIGN.md formalises it; best-reconciled descendant of the three incompatible legacy systems. Prevents a fourth colour system.
- (decision) Scope split: DESIGN.md product-wide (identity does not re-fork per epic); EXPERIENCE.md scoped to Epic-2 user-facing surfaces now (home, onboarding, import job, completion summary, failure register) with reusable foundations (IA, voice, primitives, a11y floor) for later epics to extend via Update mode.
- (decision) Home (2.11, FR-27/FR-60): top zone WORKLIST — actionable lines only, action in lawyer's language, never a technical state, aggregated+capped; below it MATTERS zone is navigation carrying each matter's scoped denominator/running/ranking-stale/sampling-open/last-touched. No line type in both zones (tested). Worklist always top.
- (decision) Permanent denominator (2.7, FR-6/FR-28/FR-57): submitted = in corpus + open failures + declared exclusions, each a countable line, nothing in two/none, no fourth bucket. On the home screen, carrying failure count and unknown-cardinality containers explicitly ('1 archive unopened, contents unknown' — never '· 1 not indexed'). Reuses ratified .apx-equation.
- (decision) Onboarding (2.1, FR-1/FR-37/FR-49): 3 mandatory (folder, matter, RBAC scope) + 1 optional (case theory, skippable) on one screen; no further mandatory config. Custodian mandatory ('custodian-undeclared' where unknown, never blank). Scope constrained to held-or-grantable, both directions. Zero-readable folder -> completed 0/0 job + explanatory worklist line; null/empty scope fails loudly.
- (decision) Import job (2.2, FR-2) non-blocking: persistent collapsed indicator of processed-against-submitted, never a modal. Survives kill/resume. 'submitted' declared provisional while enumeration/expansion runs (FR-57).
- (decision) Failure register (2.6, FR-5) resolves by STATE CHANGE never removal: filename/path/matter/custodian/error-class/cardinality/resolution-state/timestamp + retry; success->resolved keeps history; inventory counts open only. Bulk retry = one audit entry naming the set. password-protected offers credential-supply, not an override. Exportable one piece/line within scope.
- (decision) Completion summary (2.10, FR-7/FR-27): first element denominator, second the worklist lines this job generated — action in lawyer's language, clickable; non-actionable lines hidden. Counts: newly-indexed / already-present / excluded-noise / expanded-from-containers / register-by-class. Re-reachable from the matter and audit record, not transient.
- (decision) Voice: lawyer's language wherever a lawyer reads (Max review); technical state stays in register detail, never worklist. Salvaged: audit/provenance one click away; honest 'hors corpus'; never a destructive delete. Barred: engineer-facing columns (chunks), french-as-key i18n, mouse-only citations, inconsistent radii/max-widths.
- (assumption) i18n foundation: namespaced FR/EN semantic keys as peers (never french-as-key); French legal terms of art and quoted corpus text never machine-translated, marked as untranslated source. Full i18n is Epic-6; stated here as a binding foundation so Epic-2 copy is authored against it from line one.

- (change) Epic-3 UPDATE (Story 3.4 UX pass): extend the contract with the truth-status/search surface. EXPERIENCE.md stays Epic-2; add EXPERIENCE-EPIC3.md (peer contract). DESIGN.md gains the Epic-3 components (product-wide vocabulary). Binds FR-12/13/15/23/57, AD-20/38/42.
- (decision) TWO truth statuses are a DIFFERENT axis from the triage tier and are NEVER combined into one list (FR-15). SUGGESTIVE (semantic): the '≈' glyph, tone-NEUTRAL (ink-3/muted, NOT a semantic-tier colour, NOT gold), an OPEN frame (dashed left rule) signalling 'not a closed set'; eyebrow 'SUGGESTIF · classé par proximité'. EXHAUSTIVE (deterministic): the '=' glyph, and its honesty SEAL REUSES the verdict-seal pattern (kept-toned when searched over a stable fully-indexed scope; review-toned when qualified) — 'searched everything indexed' is the same shape as 'the accounting holds'. No new colour; reuse the palette.
- (decision) The truth-status badge is DATA-DRIVEN (the result set carries truth_status, one construction site per engine — already gated). Every result set, every export, and every audit entry renders it; a screen never chooses it. No interface element interleaves the two engines — if both run they are two separately-framed panels, each self-declaring.
- (decision) The absence statement (AD-42, deferred from 3.2) is the product's MOST DANGEROUS output and gets the most careful treatment: a verdict-seal-shaped honest sentence carrying the FOUR qualifications — the scoped denominator (AD-38, reuses the permanent-denominator equation), the open failure-register count, the unknown-cardinality containers in WORDS, and the OCR share + below-quality share of the SEARCHED set. Copy: 'Aucune occurrence de « X ». Recherché dans tout l'indexé de ce périmètre. Le registre liste 2 800 pièces illisibles et 1 archive au contenu inconnu ; 12 % du corpus recherché provient d'un OCR, 3 % sous le seuil de qualité.' NEVER a bare 'introuvable'; the FR-23 banned phrasing ('risque d'avoir manqué…') stays barred.
- (decision) Search entry: one field on the matter/corpus surface with an EXPLICIT mode — 'Suggestions (par sujet)' vs 'Preuve (terme exact)' — so the lawyer always knows which truth she is getting; the mode is never silently chosen. Scope chip shown; results + denominator are scoped (the 3.3 pre-filter). The register is searched SEPARATELY (AD-21): a register name-match is a distinct hit, never inside the exhaustive results.
- (decision) Similarity is shown as a RELATIVE proximity indicator + rank, never a false-precise percentage (voice rule: no false-precise single number). Suggestive count phrased 'les 20 pièces les plus proches sur ce périmètre', NEVER '20 résultats' (reads as a total/completeness). Exhaustive presence: 'N occurrences de « X » dans M pièces — ensemble complet sur ce périmètre.'
- (decision) Export survives to a court-readable format (PDF/CSV) carrying the truth status VISUALLY and VERBALLY: a suggestive export header 'SUGGESTIONS — liste non exhaustive, classée par proximité ; ne constitue pas une preuve d'absence'; an exhaustive export carries its scoped denominator + the four qualifications + the presence/absence claim — the defensible document a court reads without the system. The query is an AUDITED act: the audit entry names actor, term, engine (truth status), scope, and the denominator at that moment.
- (decision) State patterns (Epic-3): MOVING POPULATION — an open import job on the matter makes the exhaustive engine REFUSE (3.2), the UI states 'Import en cours sur ce dossier — la recherche exhaustive attend un corpus stable', never a partial set. Empty/no scope -> empty set + 0/0 denominator, fail-closed (3.3). Zero suggestive -> 'Aucune suggestion au-dessus du seuil de proximité (ce n'est pas une preuve d'absence — utilisez la recherche exhaustive).'
- (decision) Two named-protagonist flows added (Claire Fontaine, from the Epic-2 contract). Flow 5 'Prove the term appears nowhere' (the defining Epic-3 flow): exhaustive search -> the absence statement with its qualifications -> export a defensible PDF -> audited; climax = she can defend 'searched everything indexed within this scope; the register lists 2 800 unreadable and 1 archive of unknown contents', not a guess in the costume of a proof. Flow 6 'Find pièces about a topic' (suggestive): ranked suggestions clearly framed '≈ SUGGESTIF', open one at the passage; climax = she is never misled into thinking a suggestion was a proof.
